# 架构决策记录

本文件采用简化 ADR 格式，记录不能只从代码看出原因的关键选择。

## ADR-001：选择 Tauri 2 而不是 Electron

日期：2026-10-15  
状态：接受

背景：需要 Windows/macOS 双端、系统凭证库和较小安装体积。  
决策：使用 Tauri 2，前端共用，系统能力放在 Rust。  
影响：需要 Rust 工具链和平台构建环境；可减少 Node 运行时暴露面和安装体积。

## ADR-002：MVP 使用原生 TypeScript

日期：2026-10-15  
状态：接受

背景：当前只有三个页面和少量表单。  
决策：暂不引入 React/Vue，使用 TypeScript 模板渲染。  
影响：依赖更少、构建更快；页面复杂后需要评估组件化框架或拆分渲染模块。

## ADR-003：密钥只保存到操作系统凭证库

日期：2026-10-15  
状态：接受

背景：API Key 属于高敏感数据，普通 JSON、SQLite 或 `.env` 不足以满足默认安全要求。  
决策：通过 keyring 使用 macOS Keychain 和 Windows Credential Manager。  
影响：可能出现系统授权提示和企业策略差异；不提供明文降级路径。

## ADR-004：前端没有读取密钥的 IPC

日期：2026-10-15  
状态：接受

背景：即使密钥安全落盘，暴露读取命令仍会扩大 WebView 攻击面。  
决策：只提供保存和删除；快照只返回 `secret_saved`。  
影响：界面无法显示或复制既有密钥。未来远端请求由 Rust Provider 直接执行。

## ADR-005：MVP 用量采用手动录入

日期：2026-10-15  
状态：接受

背景：没有确认 Cursor 提供稳定公开的个人用量 API。  
决策：先提供可验证的手动录入，不抓取内部接口。  
影响：自动化程度较低，但功能稳定且不依赖逆向接口。

## ADR-006：不修改 Cursor 本地状态

日期：2026-10-15  
状态：接受且不可通过普通需求变更取消

背景：参考软件通过内部脚本注入、令牌替换和机器标识处理实现续杯。  
决策：本产品只检测 Cursor 是否安装，不读取或修改其认证数据库、安装文件、网络请求和设备标识。  
影响：不能实现绕过计费意义上的自动续杯；保留用量管理与合法 BYOK 的产品价值。

## ADR-007：应用默认不包含业务后台

日期：2026-10-15  
状态：接受

背景：MVP 功能均可在本地完成，服务端会增加隐私、运维和攻击面。  
决策：0.1 版本 local-first，无账号系统和远端存储。  
影响：多设备同步与团队管理延后；许可证商业化方案需另行设计。

## ADR-008：高风险机制只在隔离研究沙盒中模拟

日期：2026-10-15  
状态：接受

背景：需要理解账号池、令牌下发、设备身份变化与额度切换之间的系统关系，但不能作用于真实第三方服务。  
决策：建立独立的 `research-lab`，只监听 loopback，使用 `.invalid` 身份、`lab_tok_` 令牌、`vdev_` 虚拟设备和本地 SQLite。  
影响：可以研究状态机、429、切换和审计，但实验结果不能直接连接或控制 Cursor。
