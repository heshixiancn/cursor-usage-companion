# 技术方案

版本：0.1  
日期：2026-10-15

## 1. 总体架构

```text
┌──────────────────────────────────────┐
│ 原生 TypeScript 界面                 │
│ 概览 / 授权连接 / 设置 / 表单校验     │
└────────────────┬─────────────────────┘
                 │ Tauri invoke IPC
┌────────────────▼─────────────────────┐
│ Rust 应用核心                         │
│ 输入校验 / 数据持久化 / 平台检测       │
├────────────────┬─────────────────────┤
│ 非敏感 JSON     │ Secret Vault        │
│ 用量/设置/备注   │ macOS Keychain       │
│                 │ Windows Credential   │
└────────────────┴─────────────────────┘
```

应用是 local-first 架构。MVP 没有业务服务器，也不主动访问 Cursor 或模型服务商。未来增加同步功能时，必须通过独立 Provider 适配层并逐个审核授权方式。

独立的研究沙盒不属于桌面应用业务后台：

```text
本机测试客户端
      │ HTTP + X-Lab-Key（仅 127.0.0.1）
      ▼
Node.js 本地研究服务
路由 / 校验 / 状态机 / 额度策略 / 审计
      │
      ▼
本地 SQLite
合成账号 / 令牌哈希 / 虚拟设备 / 用量 / 审计
```

桌面应用与研究沙盒默认不互相连接。这样可避免实验状态机进入面向用户的正式功能路径。

## 2. 技术选型

| 层 | 选择 | 原因 |
|---|---|---|
| 桌面框架 | Tauri 2.12 | Windows/macOS 共用代码，安装体积小，本地能力由 Rust 控制 |
| 前端 | 原生 TypeScript + Vite 8 | MVP 交互不复杂，减少框架和运行时依赖 |
| 本地核心 | Rust 2021 | 强类型、跨平台、适合处理文件和凭证边界 |
| 安全存储 | keyring 4.2 | 统一接入 macOS Keychain 与 Windows Credential Manager |
| 非敏感存储 | JSON | 数据结构小，便于迁移、排错和备份 |
| 标识 | UUID v4 | 连接记录与系统凭证条目稳定关联 |
| 时间 | UTC/RFC 3339 | 避免跨时区和夏令时歧义 |
| 研究服务 | Node.js 24 内置 HTTP | 无外部网络客户端依赖，便于审查隔离边界 |
| 研究数据 | Node.js 内置 SQLite | 单文件本地数据、事务记账、无需独立数据库进程 |

## 3. 模块划分

### 3.1 前端

- `src/main.ts`：页面渲染、交互、Tauri IPC 调用和浏览器预览降级；
- `src/types.ts`：前后端共享概念的 TypeScript 类型；
- `src/demo.ts`：仅浏览器预览用的演示数据；
- `src/styles.css`：布局、主题、状态和响应式样式；
- `src/assets/app-icon.svg`：矢量源图标。

“研究沙盒”页面维护的令牌只存在于当前 WebView 内存中，刷新或关闭应用后不会恢复。页面只能向 Rust 命令提交预定义操作名，不能提交 URL。

浏览器预览模式只保存在内存中，不模拟系统凭证库，不应被视为安全存储验证。

### 3.2 Rust 核心

当前集中在 `src-tauri/src/lib.rs`，MVP 后按以下模块拆分：

- `models`：Settings、Connection、UsageSnapshot；
- `storage`：JSON 读写、迁移和原子保存；
- `vault`：系统凭证库接口；
- `platform`：Cursor 安装检测和平台信息；
- `commands`：暴露给前端的最小命令集；
- `providers`：未来的官方用量同步适配器。

### 3.3 Tauri 命令

| 命令 | 输入 | 输出 | 副作用 |
|---|---|---|---|
| `bootstrap` | 无 | `AppSnapshot` | 读取本地数据和环境 |
| `save_connection` | `ConnectionInput` | `AppSnapshot` | 写系统凭证库和元数据 |
| `delete_connection` | 连接 ID | `AppSnapshot` | 删除系统凭证和元数据 |
| `save_usage` | `UsageSnapshot` | `AppSnapshot` | 写用量数据 |
| `save_settings` | `Settings` | `AppSnapshot` | 写设置数据 |
| `lab_request` | 固定操作名、合成请求数据、可选 `lab_tok_` | 状态码与 JSON | 仅访问 `127.0.0.1:17840` 的白名单路径 |

所有命令返回不含密钥的完整快照，简化前端一致性。

### 3.4 本地研究沙盒

- `research-lab/src/server.mjs`：固定 loopback 监听、管理密钥校验、路由与 HTTP 错误映射；
- `research-lab/src/store.mjs`：SQLite 建表、事务、状态机和审计；
- `research-lab/src/constants.mjs`：环境标记、专用前缀和固定绑定地址；
- `research-lab/test/`：存储层与 HTTP API 自动化测试。

研究沙盒不包含真实注册、验证码、第三方登录、系统机器标识读写、代理转发或真实计费接口。令牌明文只在签发响应出现一次，数据库仅保存 SHA-256。

桌面桥接采用 Rust 标准库 TCP 客户端，不引入通用远端 HTTP 能力。操作枚举映射到固定方法和路径；主机、端口和路径都不能由前端修改。管理密钥在 Rust 层从本地文件读取，WebView 只能收到合成实验结果。

## 4. 数据模型

### 4.1 普通数据文件

```json
{
  "settings": {
    "warning_threshold": 70,
    "critical_threshold": 90,
    "notifications_enabled": true,
    "refresh_interval_minutes": 15
  },
  "connections": [
    {
      "id": "uuid",
      "label": "工作密钥",
      "provider": "openai",
      "account_hint": "dev@example.com",
      "secret_saved": true,
      "created_at": "RFC3339",
      "updated_at": "RFC3339"
    }
  ],
  "usage": {
    "used": 32.4,
    "limit": 100.0,
    "unit": "美元",
    "source": "手动录入",
    "updated_at": "RFC3339",
    "resets_at": null
  }
}
```

`secret` 不属于该结构。系统凭证库键由固定 service 名和连接 UUID 组成。

### 4.2 前端快照

前端只收到 `secret_saved: true/false`，不提供读取完整密钥的命令。即使前端页面被调试，也不能通过正常 IPC 获得密钥内容。

## 5. 关键数据流

### 添加连接

1. 用户在表单中输入元数据和 API Key；
2. 前端通过单次 IPC 调用提交；
3. Rust 验证名称、服务商、备注和凭证长度；
4. Rust 生成 UUID；
5. 先写入系统凭证库；
6. 成功后再写入非敏感 JSON；
7. 返回不含密钥的快照；
8. 前端销毁表单 DOM 并重新渲染。

### 删除连接

1. 用户二次确认；
2. Rust 验证连接 ID 存在；
3. 删除系统凭证条目；
4. 删除元数据并保存；
5. 返回新快照。

### 更新用量

1. 用户输入已用、总额、单位和重置时间；
2. Rust 验证有限数值和范围；
3. 后端强制设置数据来源与更新时间；
4. 写入 JSON 并返回新快照。

### 研究沙盒实验

1. 桌面页面提交白名单操作名；
2. Rust 将操作映射到固定 loopback 接口并附加本地管理密钥；
3. Node 服务执行 SQLite 状态机并返回带环境标记的 JSON；
4. 页面只在内存中保存当前 `lab_tok_` 和 `vdev_`；
5. 消耗返回 429 且 `should_switch=true` 时，页面请求下一合成账号；
6. 创建、签发、消耗、拒绝、切换、撤销和重置出现在审计记录中。

## 6. 错误处理

- Rust 命令统一返回 `Result<T, String>`；
- 面向用户的错误使用简短中文，不返回堆栈；
- 系统凭证库失败时不写元数据，避免出现“显示已保存但无密钥”的状态；
- 删除凭证失败暂不阻断元数据删除属于当前 MVP 的折中，正式版应区分“不存在”与“系统错误”。

## 8. 扩展原则

新增用量 Provider 必须实现：

- 明确的用户授权来源；
- 只读权限优先；
- 可撤销；
- 不保存第三方账号密码；
- 不调用未公开内部接口；
- 失败时不影响本地手动记录；
- 提供服务商、最后同步时间和错误状态。
